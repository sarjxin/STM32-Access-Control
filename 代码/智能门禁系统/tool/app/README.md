# 门禁助手 · Android App

为当前 STM32 + JDY-31 智能门禁项目制作的中文安卓客户端。使用经典蓝牙 SPP/RFCOMM，通过模块与 STM32 串口通信。源码采用 Java + 原生 Android XML，无第三方界面或蓝牙库。

## 安装与连接

1. 将 `output/DoorAccess-v1.2.apk` 传到安卓手机，打开并按手机提示允许该文件来源安装应用。已安装 v1.0 / v1.1 时可直接覆盖更新，保留已有设置。
2. 给 JDY-31 通电，打开手机的系统蓝牙设置，找到模块并配对。手册的默认名称为 `JDY-31-SPP`，默认配对 PIN 为 `1234`；实际以你的模块设置为准。
3. 打开“门禁助手”，进入“设备连接”。安卓 12 及以上点击刷新后，需要允许“附近设备”权限。
4. 从已配对列表选择你的模块，点击连接。App 不启动设备扫描，也不请求定位权限。
5. 连接成功后，点击“查询状态”。STM32 必须返回约定的完整回执，App 才显示已上锁/已解锁。
6. 点击“开锁”或“上锁”发送对应指令。收到回执后显示门锁报告的状态。
7. 点击“退出”发送 `exitToMemu`，沿用设置里的发送结束符（默认 CRLF）。用于通知 STM32 返回菜单；发送完成后保持蓝牙连接，不要求退出回执。

APK 使用本机 D 盘的调试密钥签名，适用于本项目安装和联调。保留 `D:\app\android\user-home\.android\debug.keystore`，以后同签名 APK 可以更新安装。

## 三个页面

v1.2 将已确认的网页设计应用到原生界面：深海蓝背景、青蓝强调色、状态光环、图标导航。开锁/上锁为大按钮，查询与退出菜单为并排的次要按钮；等待、成功、拒绝和超时使用清楚的文字反馈。输入框、下拉菜单及系统栏均采用深色样式。装饰由原生 XML、矢量图标和 Canvas 绘制，无外部字体或图片下载。

- **门锁控制**：连接状态、门锁报告状态、开锁、上锁、查询状态、退出、当前设备。
- **设备连接**：系统蓝牙设置入口、已配对设备列表、连接和断开。上次选择的设备优先显示。
- **设置与联调**：三个控制指令、发送结束符、两种状态回执配置；文本/HEX 手动发送；最近 120 条内存通信记录，最新记录在上方。完整报文另外显示，便于查看分批接收的中文。

连接建立后不会自动发送控制指令。App 不自动重连或重发开锁/上锁指令。App 进入后台或关闭时会断开连接；再次使用需要重新连接和查询状态。控制页的“退出”只发送 STM32 菜单退出指令。旋转屏幕保持当前页面与连接。

## 默认协议

| 操作 | 手机发送的实际内容 | STM32 返回 |
|---|---|---|
| 开锁 | `UNLOCK\r\n` | `STATE:UNLOCKED\r\n` |
| 上锁 | `LOCK\r\n` | `STATE:LOCKED\r\n` |
| 状态查询 | `STATUS\r\n` | 返回当前的 `STATE:LOCKED\r\n` 或 `STATE:UNLOCKED\r\n` |
| 退出菜单 | `exitToMemu\r\n` | 未约定回执；App 只提示指令已发送 |
| 拒绝或执行失败 | — | `ERR:原因\r\n` |

这里 `\r` 是字节 `0D`，`\n` 是字节 `0A`，不是反斜杠和字母。手机发送的开锁字节为 `55 4E 4C 4F 43 4B 0D 0A`。

**当前 STM32 工程的蓝牙业务协议需要你自己实现。** 本次只新增 `tool/app` 下的安卓工程，没有修改 MCU 源码。完整接口、超时规则和联调方法见 [通信协议.md](通信协议.md)。

## 状态与失败处理

- 建立蓝牙连接、输出流写入成功，都不会把锁状态改成“已解锁”或“已上锁”。
- 状态回执采用完整行、区分大小写的精确匹配。设置里的“发送结束符”仅作用于发送；接收回执始终需以 CR 或 LF 结束。
- 一次只允许一条控制指令等待回执。5 秒未收到有效回执时显示结果未确认，并断开连接，避免迟到回执影响下一次操作。
- 收到错误回执时显示拒绝原因。返回相反的状态时明确提示状态不一致。
- 断线、重新连接、修改指令配置时，旧状态失效。界面显示的是 MCU 报告的锁状态；确认门是否真正关好需要相应传感器。
- 接收数据支持拆包、粘包、跨块 CRLF 和 UTF-8。单行接收上限 1024 字节，手动发送上限 512 字节。

## 构建、测试和磁盘路径

开发环境已装在 `D:\app\android`。项目、构建产物和 APK 位于本 E 盘目录。

双击 `build.cmd`，或者在 PowerShell 中执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build.ps1
```

脚本会加载 D 盘环境，运行协议测试、构建 APK、执行 Android lint 和签名检查，最后复制 APK 到 `output` 并生成 SHA-256 文件。也可以只运行 `test.ps1` 检查协议解析。

| 内容 | 路径 |
|---|---|
| 项目级缓存和构建产物 | 本目录的 `.gradle`、`app/build`、`build`、`test-output` |
| APK、日志、验证记录 | 本目录的 `output` |
| JDK / SDK / Gradle | `D:\app\android\jdk`、`sdk`、`gradle` |
| Gradle 全局缓存 | `D:\app\android\gradle-home` |
| Android 用户数据、调试签名 | `D:\app\android\user-home\.android` |
| Java 用户目录、临时文件 | `D:\app\android\user-home`、`D:\app\android\temp` |

请使用配套构建脚本，以维持上述路径设置。没有安装模拟器，也没有修改系统环境变量。Windows 和安全软件自身的 C 盘写入不受本项目控制。

## 常见问题

- **列表里没有 JDY-31**：先在系统蓝牙设置里配对，回到 App 后刷新；模块可能已被另一个手机占用。
- **配对成功但 App 连接失败**：确认是 JDY-31 的经典 SPP 模块，权限已允许、模块已通电，其他蓝牙串口应用已断开。
- **App 已连接，但 STM32 无数据**：检查模块 TX/RX 与 MCU RX/TX 交叉连接、共地、UART 配置。手机端没有串口波特率设置；波特率和数据格式由 MCU 与模块两端配置一致。
- **点击操作总是超时**：到联调页查看 TX、RX 和完整报文，确认指令、回执、大小写和换行。只有回显 `UNLOCK` 或返回 `OK` 不会确认锁状态。
- **HEX 发送的数据多了换行**：HEX 模式不会追加结束符；如需换行，请自己加 `0D 0A`。只有文本模式自动添加已保存的结束符。
- **返回 App 后连接断开**：这是前台连接策略，重新连接并查询即可。

## 验证范围

本机进行了协议与事务检查、APK 编译、Android lint 和签名验证，结果记录在 `output/验证记录.md`。未使用真实手机或 JDY-31 进行无线连接和舵机联调，实际收发及界面显示需要在你的手机上验证。

蓝牙系统配对不等于 MCU 的门禁授权。此默认文本协议未实现业务身份验证或防重放。真实门禁的开锁授权需要由 STM32 检查；手机本地界面不能替代该检查。
